# ШАБЛОНЫ FBD ДЛЯ ЭМУЛЯТОРОВ (8080 / Z80 / 6502) В CODESYS

Проверенные конструкции, на которых собран эмулятор 8080 (199/199 кейсов,
10/10 проверок I/O). Всё генерируется в PLCopenXML из Python; для Z80/6502
конструкции те же.

---

## 1. СЕМАНТИКА БАЗОВЫХ БЛОКОВ (запомнить намертво)

| Блок | Семантика | Опасность |
|---|---|---|
| `SEL(G, IN0, IN1)` | **IN1 при G = TRUE** | легко перепутать местами |
| `IF(cond, a, b)` | a при cond, иначе b | это ДРУГОЙ блок, не SEL |
| `AND`, `OR` | РОВНО 2 входа | 3+ операнда → ошибка/сдвиг аргументов |
| `SHL`, `SHR` | разрядность входа важна | `SHL(BYTE, 8) = 0` |

**Обязательный хелпер** (единственный способ не путаться):

```python
def SEL_COND(n, cond, when_true, when_false, x=None, y=None):
    u"""SEL с ЯВНЫМ порядком: cond ? when_true : when_false."""
    return n.block(u"SEL", [(u"G", cond),
                            (u"IN0", when_false),   # G = FALSE
                            (u"IN1", when_true)],   # G = TRUE
                   [u"OUT"], x, y)
```

Для трёх и более операндов — деревья:

```python
def ORL(n, items, x0=None):   # OR по списку
def ANDL(n, items, x0=None):  # AND по списку
```

Для цепочки «последний имеет приоритет»:

```python
def CHAIN(n, base, steps):
    u"""steps = [(cond, value), ...]; ПОСЛЕДНИЙ шаг перекрывает предыдущие."""
    acc = base
    for cond, val in steps:
        acc = SEL_COND(n, cond, val, acc)
    return acc
```

## 2. ЗАПИСЬ В МАССИВ ПО КОНСТАНТНЫМ ИНДЕКСАМ

**Нельзя:** `outvar(u"Memory[addr]", value)` — импортёр такую запись ТЕРЯЕТ.

**Можно** (проверено на 256 элементах):

```python
def write_indexed(n, array_name, idx_expr, val_expr, size, gate=None):
    u"""Массив[k] := gate AND (idx = k) ? val : Массив[k]  для всех k."""
    for k in range(size):
        e = u"%s[%d]" % (array_name, k)
        hit = AND(n, EQ(n, idx_expr, I(n, u"INT#%d" % k)))
        if gate is not None:
            hit = AND(n, gate, hit)
        n.outvar(e, IF(n, hit, val_expr, I(n, e)))
```

**Как выбрать размер:**
- память 64 КБ — НЕ делать 65536 присваиваний;
- вместо этого — блок FB с входом `Addr` (в нашем случае `FB_Memory64K`),
  но проверить, что он реально исполняется (см. п. 3);
- для малых массивов (8/16/64/256) — прямое использование.

**Проверка, что работает:** записать и сразу прочитать в том же скане:
```
писать:  Memory[0x600] := 0x01   (константный индекс)
читать:  что лежит — защёлкнуть в диагностику
```
Если 0 — запись не сгенерирована.

## 3. ПРАВИЛО ПОТРЕБЛЁННОГО ВЫХОДА FB

**Тело вызова FB генерируется только если хотя бы один выход ЧИТАЕТСЯ, причём
глобально** (локальная неиспользуемая переменная не считается).

```python
# ПЛОХО: output -> локальная pw_val, которую никто не читает => блока нет
n.outvar(u"pw_val", blk.out(u"DataOut"))

# ХОРОШО: output -> глобальная диагностика (или в логику)
n.outvar(u"GVL_TEST.Dbg_Wr", blk.out(u"DataOut"))
```

**Признак в отчёте:** «запись не произошла», хотя блок в схеме есть.

## 4. РЕГИСТРОВЫЙ ФАЙЛ: ОДНА ЗАПИСЬ НА ТАКТ

Шаблон (проверен на 8080, годится для Z80 с оговоркой про IX/IY):

```
FB_RegFileQ:
  Data1, Dst1, Wr1   -> порт 1  (A, пары)
  Data2, Dst2, Wr2   -> порт 2  (флаги, вторичные)
```

Правила:
- `Wr` = `run_i AND разрешение_записи AND NOT(особый_случай)`;
- для `LXI SP` порты регистров гасятся, SP пишется отдельным путём;
- все промежуточные значения — в переменных POU, но с учётом задержки в скан.

**Частая ошибка:** признак записи (`wr1a`) не содержит одной из групп команд →
половина регистров не пишется. Список групп должен покрывать ВСЕ команды,
пишущие регистры.

## 5. ПАМЯТЬ: АДРЕС, ДАННЫЕ, РАЗРЕШЕНИЕ

```
rd_addr  = CHAIN(0, [(sel=1, a16), (sel=2, BC), (sel=3, DE), (sel=4, SP), (sel=5, HL)])
rd_val   = Memory[rd_addr]       (* через блок с входом Addr *)
rd_val2  = Memory[rd_addr + 1]
wr_addr1 = CHAIN(HL, [(k_sta, a16), (k_shld, a16), (k_stax, pair), (push, SP-1), ...])
wr_addr2 = CHAIN(HL, [(k_shld, a16+1), (push, SP-2), ...])
```

**Не забыть:** адрес чтения и адрес записи — РАЗНЫЕ цепочки. У 6502 их
больше (нулевая страница, (zp,X), (zp),Y, абсолютная, (abs)).

## 6. АЛУ: ОПЕРАНДЫ И ФЛАГИ

```
alu_a = is_incdec ? srcval : A          (* у INR/DCR операнд — источник *)
bval  = is_incdec ? 1 : (k_alui ? op_lo : srcval)
R     = OP(alu_a, bval, cin)
```

Флаги:
- `cin` для ADC/SBB: `cineff = SEL(is_sbb, cin, NOT(cy))` — не «инвертировать
  AC/CY пачкой», а менять по одному флагу;
- `P` = NOT(XOR всех бит) (для Z80/6502 лучше таблица 256 значений);
- `AC` для вычитания — отдельный расчёт, проверять по эталону;
- для DAA/CMP обязательны отдельные разрешения записи (`AC_En`, `CY_En`,
  `SZP_En`) и отдельный выбор `cy_new` по признаку команды.

**Правило:** в память пишут только команды с приёмником-памятью
(`wr_reg_dst AND mdst`), STA/STAX/SHLD/XTHL и стек. Альтернатива «источник
из памяти → писать в память» — ОШИБКА.

## 7. СТЕК

```
PUSH:   Memory[SP-1] := hi ; Memory[SP-2] := lo ; SP := SP-2
POP:    lo := Memory[SP] ; hi := Memory[SP+1] ; SP := SP+2
CALL:   толкать адрес возврата ТОЛЬКО при выполнении условия
RET:    снимать SP, грузить PC из стека
```

Данные для PUSH:
```
push_data = SEL_COND(is_ret_addr, ret_*, pair_*)
   where is_ret_addr = k_call OR k_rst OR k_int
```
(для PUSH — пара; для CALL/RST/прерывания — адрес возврата).

SP:
```
sp := CHAIN(sp, [(pushlike AND run AND (NOT(k_call) OR take), sp_push),
                 (pop AND run, sp_pop),
                 (is_step, sp_adj),
                 (k_sphl, HL),
                 (is_sp_incdec, sp_adj),
                 (is_lxi_sp, a16)])
```
**Условный CALL не должен уменьшать SP.**

## 8. ПЕРЕХОДЫ: ГДЕ NEXT-PC

```
target  = a16 (или HL для PCHL, или адрес обработчика для RST/INT)
take    = uncond_eff OR cond_met
pc_ctrl = take ? target : pc + len
pn      = is_branch ? pc_ctrl : pc + len
pc      := pn
```
где `uncond_eff = (C_Uncond AND is_jcr) OR is_vec`, а `C_Uncond` истинно
только для безусловных форм (`JMP 0xC3`, `CALL 0xCD`, `RET 0xC9`).

**Проверять защёлкой:** `C_Uncond`, `take`, `pc_ctrl` — мы нашли дефект
именно так (`Uncond = 1`, но перехода нет → неверный `is_branch`).

## 9. ТАКТ: ОДИН ЗА СКАН + ХОЛОСТЫЕ СКАНЫ

```
settle := IF(f_run, IF(GE(settle, SETTLE), 0, settle + 1), 0)
fire   := AND(f_run, GE(settle, SETTLE))
CPU_Run := IF(own, fire, CPU_Run)
tact   := IF(f_run, IF(fire, tact + 1, tact), 0)
stop_now := AND(f_run, GE(tact, c_tacts))
```

Это компенсирует задержку `outvar/invar` (один скан на сетевое звено).
Для Z80/6502 обязательно из-за длинных тактов.

## 10. ВМЕШАТЕЛЬСТВО ТЕСТА В ШИНУ

```
(* процессор пишет шину каждый скан *)
GVL_IO.Req := cpu_req

(* тест пишет отдельный бит *)
GVL_IO.Inj := test_inj

(* потребитель видит сумму *)
req_to_device := GVL_IO.Req OR GVL_IO.Inj
```

Без этого тест не может ничего инжектировать: процессор затирает.

## 11. ОКНА ФАЗ ТЕСТА

```
(* ПЛОХО: два флага фаз — у каждого задержка в скан, окно рвётся *)
window = _one(IP_I10) OR _one(IP_W10)

(* ХОРОШО: диапазон по номеру фазы *)
window = GE(ph, IP_I10) AND LE(ph, IP_W10)
```

## 12. ФАЗЫ ТЕСТА ДОЛЬШЕ ОДНОГО СКАНА

```
sc2 := IF(ph <> ph_prev, 1, sc2 + 1)
hold := GE(sc2, 4)          (* 4 скана на фазу *)
переход : cond AND hold
```

Зачем: POU, исполняющиеся РАНЬШЕ теста в задаче, видят его сигналы только
следующим сканом. При фазе в один скан запрос не доходит никогда.

**Порядок вызова в задаче фиксировать и помнить:**
`TEST_8080 → PLC_PRG_CPM (ядро + I/O + CP/M) → TEST_CPM → TEST_IO`

## 13. СТАРТ СИСТЕМЫ (ОС / МОНИТОР)

Ошибка: писать PC := вектор при работающем процессоре → PC = 0.

Правильно:
```
1. CPU_Run := FALSE   (1–2 скана)
2. PC/SP через порт:  WE=TRUE, Sel1=7 (PC), Data1=vector, LD1=TRUE
3. CPU_Run := TRUE
```

Инициализацию в самом трапе/мониторе делать **идемпотентной**: она должна
повторяться по фронту «режим входа в систему», а не один раз при старте ПЛК.

## 14. ДИАГНОСТИКА В СХЕМЕ

```
ActIR[idx]  := IF(f_run, Bus_IR,  ActIR[idx])     (* массив на кейс *)
ActAddr[idx]:= IF(f_run, Bus_Addr, ActAddr[idx])
Dbg_Scan    := Dbg_Scan + 1                        (* счётчик вызовов *)
Dbg_Req     := IF(Req, Dbg_Req + 1, Dbg_Req)       (* счётчик событий *)
Dbg_Max     := IF(x > Dbg_Max, x, Dbg_Max)         (* максимум *)
Dbg_SD      := IF(io_done, Dbg_N, Dbg_SD)          (* метка скана *)
```

Все диагностические переменные — **глобальные** (в GVL), иначе компилятор
выбросит цепочку вместе с телом блока.

## 15. ТЕСТОВАЯ ТАБЛИЦА КЕЙСОВ

Один кейс — запись в массиве структур:
```
type ST_TestCase :
  Id, Name, Group
  Code   : ARRAY[0..15] OF BYTE;   (* программа *)
  Init   : регистры, PSW, SP
  Exp    : регистры, PSW, SP, PC, маска PSW
  Pre1Addr/Pre1Val, Pre2..., Pre3...
  MemAddr/MemVal/ChkMem
  Tacts
```

Прогон: загрузка кода → MEM (код + предустановки) → W1..W5 (запись
регистров) → RUN (такты) → CMP (сверка) → NEXT.

**Важно:** предустановки памяти писать по КОНСТАНТНЫМ индексам (см. п. 2),
иначе тест «врёт» сам себе.
