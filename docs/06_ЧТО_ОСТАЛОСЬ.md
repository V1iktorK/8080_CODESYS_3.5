# ЧТО НАДО ДОДЕЛАТЬ ПО ДВУМ ТЗ

Документ составлен по состоянию проекта `8080_EMU` на момент фазы B.
Охватывает **два задания**: (ТЗ-1) сам эмулятор Intel 8080 и (ТЗ-2) операционную
систему CP/M с аппаратной обвязкой.

---

## ТЗ-1. ЭМУЛЯТОР INTEL 8080 В CODESYS 3.5

### 1.1. Требования ТЗ-1 и их состояние

| № | Требование ТЗ-1 | Состояние |
|---|---|---|
| 1 | Реализация на CODESYS 3.5, работает в режиме симуляции | **ВЫПОЛНЕНО** (0 ошибок, RUN, 10 000+ сканов) |
| 2 | Только FBD; вспомогательные FB допустимы, их логика тоже FBD | **ВЫПОЛНЕНО** (94 POU, 5255 блоков FBD) |
| 3 | ST только для инициализации памяти и тестовых данных | **ВЫПОЛНЕНО** |
| 4 | CFC не использовать | **ВЫПОЛНЕНО** |
| 5 | Готовые библиотеки эмуляторов не использовать | **ВЫПОЛНЕНО** |
| 6 | Команды MOV, MVI, ADD, SUB, INR, DCR, JMP, JZ, JNZ, CALL, RET, HLT | **СХЕМА ЕСТЬ, ИСПОЛНЕНИЕ НЕ ПОДТВЕРЖДЕНО** |
| 7 | Регистры A,B,C,D,E,H,L (BYTE), PC,SP (WORD) | **ВЫПОЛНЕНО** |
| 8 | Флаги S, Z, AC, P, CY | **ВЫПОЛНЕНО** |
| 9 | Память `ARRAY[0..65535] OF BYTE` | **ВЫПОЛНЕНО** |
| 10 | Единая шина `GVL.Bus_Data : BYTE` | **ВЫПОЛНЕНО** |
| 11 | Распаковка BYTE -> `ARRAY[0..7] OF BOOL` масками и сдвигами | **ВЫПОЛНЕНО** (`FB_UnpackByte`) |
| 12 | Один такт = один скан PLC | **ВЫПОЛНЕНО** |
| 13 | Порядок через Execution Order | **ВЫПОЛНЕНО** |
| 14 | **Доказательство работоспособности — прогон тестов** | **НЕ ВЫПОЛНЕНО: 0 PASS из 199** |

### 1.2. Что конкретно доделать по ТЗ-1

1. **Заставить прогонный автомат `TEST_8080` реально выполнять такты.**
   Сейчас `Idx = 0`, `Pass = 0`, `Fail = 0`: автомат уходит в фазу HAND, не
   выполнив ни одного кейса. Причина — состояние автомата (локальные `idx`,
   `ph`, `tact`) сохраняется в проекте между запусками и не сбрасывается.
2. **Прогнать 199 кейсов и получить 100 % PASS.** Именно это, а не «0 ошибок
   компиляции», является доказательством, что требования 6–13 ТЗ-1 выполнены.
3. **Разобрать расхождения по группам кейсов** (MOV/MVI/ADD/SUB/INR/DCR/
   переходы/стек) после того, как прогон пойдёт.

## ТЗ-2. ОПЕРАЦИОННАЯ СИСТЕМА CP/M 2.2 И АППАРАТНАЯ ОБВЯЗКА

### 2.1. Требования ТЗ-2 и их состояние

| № | Требование ТЗ-2 | Состояние |
|---|---|---|
| 1 | Полный эмулятор 8080 (а не только 12 команд) | **СХЕМА ЕСТЬ** (полный декодер), исполнение не подтверждено |
| 2 | «Настоящая» CP/M 2.2: BIOS, BDOS, CCP | **ЧАСТИЧНО**: CCP загружается (`PC = 0F100h`), консоль печатает, но 7 из 8 проверок FAIL |
| 3 | Векторы RST и нулевая страница | **ВЫПОЛНЕНО** |
| 4 | FCB 36 байт, директория 32x64, блоки 1 КБ | **ВЫПОЛНЕНО** |
| 5 | Виртуальный дисковый образ | **ЧАСТИЧНО**: образ есть, профиль `HARD_8M` не собран |
| 6 | Аппаратный слой I/O: порты -> %I/%Q/%IW/%QW | **ЧАСТИЧНО**: 3 из 10 проверок PASS |
| 7 | Watchdog | **СХЕМА ЕСТЬ**, проверка FAIL |
| 8 | HMI | **СХЕМА ЕСТЬ**, страница VISU не создана |
| 9 | Никакого ST для логики CP/M и I/O | **ВЫПОЛНЕНО** |

### 2.2. Что конкретно доделать по ТЗ-2

1. **Довести проверки CP/M до PASS** (`TEST_CPM`): приглашение `A>`,
   эхо команды `DIR`, имена файлов в каталоге, возврат приглашения,
   эхо `TYPE README.TXT`, содержимое файла, счётчики CCP и ловушек.
2. **Довести проверки ввода-вывода до PASS** (`TEST_IO`): `OUT 00h -> DO[0]`,
   `OUT 20h -> AO[0]`, порт без канала (STUB и FAULT), `IN` через процессор
   (wait state), тайм-аут watchdog.
3. **Реальный `.COM`.** Сейчас память содержит только точки входа-заглушки.
   Нужно, чтобы с диска загружался и исполнялся настоящий файл `.COM`
   (например `HELLO.COM`), а не HLE-имитация.
4. **Снять заглушки.** BIOS `LIST`/`PUNCH`/`READER` и BDOS 24 возвращают
   заглушки — либо реализовать, либо документировать как неподдерживаемые.
5. **Прерывания** 8080 (RST, EI/DI, INTR) — проверить в работе.
6. **Профиль диска `HARD_8M`** (SPT=128, BSH=5, DSM=2047, DRM=1023) — собран
   в коде, но ни разу не прогонялся.
7. **Страница VISU** для HMI.
