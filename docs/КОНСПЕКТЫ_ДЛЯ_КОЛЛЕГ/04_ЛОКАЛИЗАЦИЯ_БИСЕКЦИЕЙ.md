# 04. ЛОКАЛИЗАЦИЯ ОШИБКИ БИСЕКЦИЕЙ

Headless-компилятор не говорит, **где** ошибка. Этот файл — про то, как
заставить его сказать это косвенно, за ~7 сборок.

---

## 4.1. Идея

Обозначим `T(S)` = «ошибка есть, если **опустошить тела** POU из множества S».

* `T(пусто)` = истина (ошибка есть в полном проекте);
* `T(все)` = ложь (если опустошить всё — ошибке негде жить).

Делим кандидатов `cur` на `A` и `B`:

```
T(A) = ложь   -> ошибка ВНУТРИ A  -> cur := A
T(A) = истина -> ошибки в A нет   -> cur := B
```

Ошибка одна, значит после `log2(N)` сборок остаётся один POU.
Для 67 POU это 7 сборок вместо перебора.

---

## 4.2. КЛЮЧЕВОЕ: опустошать ТЕЛА, а не удалять POU

Это то, на чём провалились две первые попытки.

**Удаление POU ломает ссылки:** вызывающий не находит тип, получает
`C0046`/`C77`, кодогенерация для него **пропускается** — и искомая ошибка
**маскируется** под каскадом.

**Опустошение тела** оставляет интерфейс (все объявления) и убирает сети:

```python
for p in POUS:
    if p.name in _want:
        p.networks = []          # тело пусто, объявления на месте
```

Проект остаётся **самосогласованным**: все типы на месте, ссылок на
несуществующее нет, каскада нет.

Управление через переменную окружения — раннер передаёт список имён:

```python
_empty = [s for s in (os.environ.get("DSH_BISECT_EMPTY") or "").split(",") if s]
if _empty == ["*"]:
    _empty = [p.name for p in POUS]      # опустошить всё
```

## 4.3. ПЯТЬ УРОВНЕЙ (нам понадобились все)

| Уровень | Что делим | Как включается |
|---|---|---|
| 1 | тела 67 POU | `DSH_BISECT_EMPTY` = список имён |
| 2 | сети одного POU | `DSH_BISECT_NET_POU` + `DSH_BISECT_NET` |
| 3 | элементы одной сети | `DSH_BISECT_ITEM_KEEP` (префикс) |
| 4 | сети зависимости | `DSH_BISECT_DEP_POU` + `DSH_BISECT_DEP_KEEP` |
| 5 | элементы сети зависимости | `DSH_BISECT_DEP_ITEM_*` |

### Уровень 2: СУФФИКС, а не произвольное подмножество

Связи в FBD ссылаются **только назад** (на более ранний элемент).

* Опустошив ПЕРВЫЕ сети, вы оставите последующие ссылки на несуществующие
  элементы → XML неразборный, сборка падает, не дойдя до компиляции.
* Опустошая **суффикс** (сети `k..N-1`), вы оставляете префикс `0..k-1`,
  который ссылается только на себя — **ссылки целы**.

`T(k)` монотонна: `T(0)` = ложь (опустошено всё), `T(N)` = истина (тело цело).
Ищем `k* = min{k : T(k)=истина}` — ошибка в сети `k*-1`.

### Уровень 3: ПРЕФИКС элементов

То же самое: оставляем первые `k` элементов сети. Префикс всегда корректен,
потому что у любого оставленного элемента все источники тоже в префиксе.

**Подвох:** при усечении сети нужно оставлять **только эту сеть**, а остальные
сети POU убрать. Иначе последующие сети ссылаются на усечённые блоки → XML
неразборный → результат бисекции **артефакт**. Мы так получили ложный ответ
(«виновник — последний блок EQ»).

### Уровень 4: не забыть про зависимости

**Пустое тело вызывающего маскирует ошибку в вызываемом.** Тело FB
генерируется только если его кто-то вызывает. Пока вы опустошаете вызывающий
POU, ошибка в зависимости исчезает — и вы делаете ложный вывод «зависимости
чисты».

Именно так мы полдня искали ошибку не там: ошибка была в `FB_ALU8`, но чтобы
её увидеть, нужен **живой вызов** из `FB_CPU8080_FULL`.

## 4.4. Реализация раннера

`tools/run_bisect.ps1` — цикл, где каждая сборка = отдельный процесс CODESYS:

```powershell
function Invoke-Build {
    param([string[]]$Empty, [string]$Label)
    for ($a = 1; $a -le $BuildAttempts; $a++) {
        $env:DSH_BISECT_EMPTY = ($Empty -join ',')
        & $Runner -Script $Script -MaxAttempts 1 -RunTimeoutSec $Timeout -NoSrcCopy
        # успех = лог непустой И в stderr есть "Компиляция завершена"
        # C32 есть/нет - по строке "C32" в stderr
    }
}
```

Обязательно: повторять попытку, если прогон «не состоялся» (занятый мьютекс).
И печатать в журнал `скрипт=… компиляция=… C32=…` — иначе непонятно, что
произошло.

---

## 4.5. Сколько это стоит

У нас: 76 секунд на сборку, 67 POU → 7 итераций ≈ 9 минут на уровень.

Это **быстрее**, чем искать глазами: четыре независимых ручных поиска не дали
результата за несколько часов.

---

## 4.6. Чек-лист бисекции

1. Убедиться, что ошибка воспроизводится (`T(пусто)=истина`).
2. Шаг 0: опустошить ВСЁ. Если ошибка исчезла — она в POU; если осталась — в
   зависимостях/DUT/GVL.
3. Делить пополам, не забывая про **суффикс** для сетей.
4. Найдя POU — проверить, что опустошение ТОЛЬКО его убирает ошибку.
5. Не забыть, что зависимости проверяются только при **живом** вызове.
6. Каждый шаг писать в журнал; при «сборка не состоялась» — повторять.
