# 01. ОКРУЖЕНИЕ И СБОРКА

Всё, что нужно, чтобы CODESYS вообще начал исполнять ваши скрипты. Здесь
каждый пункт — результат потерянного времени.

---

## 1.1. Запуск из командной строки

```
"C:\Program Files (x86)\CODESYS 3.5.17.30\CODESYS\Common\CODESYS.exe" ^
  --profile="CODESYS V3.5 SP17 Patch 3" --runscript="C:\stage\build.py" --noUI
```

Профиль (`--profile`) обязателен. Без него CODESYS откроет GUI и повиснет.

### Язык скриптов — IronPython 2.7.7

Это **Python 2**. Отсюда:

* `print` без скобок допустим, но лучше `L(...)`;
* строки по умолчанию — байтовые: любой русский текст пишите как `u"..."`;
* `unicode(s)` есть, `str(s)` на кириллице падает;
* f-строк нет, распаковка в параметрах ограничена.

**Проверка:** `L(u"python: %s" % sys.version)` в начале сборки. У нас это
`2.7.7 (CODESYS.exe CODESYS V3.5 SP17 Patch 3, ScriptEngine.plugin 4.0.0.0)`.

## 1.2. ГЛАВНАЯ ГРАБЛЯ: глобальные объекты видны только в главном скрипте

В главном скрипте доступны `projects`, `system`, `online`,
`device_repository`. **В импортированных модулях их нет.**

```python
# главный скрипт - работает
proj = projects.open(path)

# в модуле mylib.py - НЕ РАБОТАЕТ (NameError)
# надо так:
import scriptengine
proj = scriptengine.projects.open(path)
```

Мы потеряли на этом несколько запусков: скрипт падал на импорте модуля, лог
оставался пустым, раннер молча повторял попытку.

**Правило:** любой вспомогательный модуль обращается к среде только через
`scriptengine.*`.

## 1.3. CODESYS не работает с путями OneDrive

Файлы проекта лежали в `C:\Users\<user>\OneDrive\Рабочий стол\CODESYS\...`.
Проявления:

* `os.path.isdir()` на существующий каталог отвечает `False`;
* `os.makedirs()` уходит в рекурсию до `C:` и падает с
  `OSError: Данный формат пути не поддерживается`;
* чтение `.py` из этой папки не удаётся;
* лог-файл создаётся пустым.

**Решение — staging.** Скрипты копируются в локальную папку
(`C:\dsh8080\work\stage`), оттуда запускаются, а рабочий корень передаётся
переменной окружения:

```powershell
$env:DSH_EMU_ROOT = 'C:/dsh8080/work/emu'
$env:DSH_EMU_ROOT = $env:DSH_EMU_ROOT.Replace('\','/')   # прямые слэши!
```

В скрипте:

```python
ROOT = os.environ.get(u"DSH_EMU_ROOT").replace(u"\\", u"/")
```

Обратные слэши в путях ломают IronPython — всегда приводите к прямым.

## 1.4. Логи: писать построчно, иначе потеряете всё

CODESYS в этом окружении убивают через `taskkill`, и **буферизованный лог
теряется целиком**. Лог остаётся нулевого размера, хотя скрипт работал минуты.

**Правило:** каждая строка — отдельное открытие/запись/закрытие файла.

```python
def L(msg):
    f = io.open(path, u"ab")
    f.write((unicode(msg) + u"\n").encode(u"utf-8"))
    f.close()
```

Медленно, но это единственный способ гарантировать запись на диск.

### Лог должен иметь резервные пути

Если основной путь не принимается (см. 1.3), скрипт падает на первой строке
и прогон теряется. Держите список кандидатов и пишите в первый удачный.

## 1.5. Раннер: почему нужен свой и что он делает

`tools/run_stage4.ps1` — обёртка вокруг запуска. Что в ней важно:

1. **Ожидание «тихого окна».** CODESYS однопроцессный. Если соседний проект
   держит его, наш запуск молча завершается, **не выполнив скрипт** (пустой
   лог). Ждём, пока процессов `CODESYS.exe` не будет N секунд подряд.
2. **`taskkill /F /T /IM CODESYS.exe`** в цикле перед попыткой — снимаем
   зависшие процессы-сироты.
3. **Удаление старых логов ДО запуска** — иначе «лог непустой = успех»
   сработает на прошлом файле.
4. **Повторы.** Попытка считается неудачной, если лог пуст или не содержит
   маркера `=== DONE ===`.
5. **Удаление `*.~u`** — файлы блокировки проекта. Если они остались,
   `projects.create()` будет падать вечно.

### ИМЯ ЛОГА ОБЯЗАНО СОВПАДАТЬ С ИМЕНЁМ СКРИПТА

Раннер ищет `<имя скрипта>.log`. Если внутри скрипта написано
`make_log("gen_stage4.log")`, а сам файл называется `gen_t1.py`, раннер лога
не найдёт и **повторит прогон 8 раз**, сжигая по 1.5 минуты на попытку.

## 1.6. Создание проекта с нуля

```python
import scriptengine
proj = scriptengine.projects.create(path)

# CODESYS Control Win V3: type=4096, id="0000 0001", version="3.5.17.30"
dev = proj.add(name=u"Device", type=4096, id=u"0000 0001",
               version=u"3.5.17.30")
app = proj.active_application

gvl = app.create_gvl(u"GVL_CPU")
gvl.textual_declaration.replace(u"VAR_GLOBAL\n\tEnable : BOOL;\nEND_VAR\n")

dut = app.create_dut(u"ST_Case", type=scriptengine.DutType.Structure)
dut.textual_declaration.replace(u"TYPE ST_Case :\nSTRUCT\n...\nEND_STRUCT\nEND_TYPE\n")

app.import_xml(path_to_plcopenxml_pou)
app.build()
```

### Кодогенерация включается только при наличии конфигурации задач

Это отдельная ловушка. Пока в проекте нет `TaskConfiguration`, `app.build()`
выполняет **только разбор объявлений**. Ошибки кодогенерации (а их было 489)
не появляются вовсе — и создаётся ложное впечатление, что проект чист.

```python
tc = app.create_task_configuration()
task = tc.create_task(u"MainTask")
task.kind_of_task = scriptengine.KindOfTask.Cyclic
task.priority = u"1"; task.interval = u"T#2ms"
task.pous.add(u"MAIN", u"главная программа")
app.build()          # вот ТЕПЕРЬ видны все ошибки
```

## 1.7. Онлайн-сессия (симуляция)

```python
oa = scriptengine.online.create_online_application(app)
oa.login(scriptengine.OnlineChangeOption.Never, False)
oa.start()
L(u"state=%r" % oa.application_state)     # ожидаем ...ApplicationState.run
...
oa.stop(); oa.logout()
```

### Запись значений: метода `write_value` НЕ СУЩЕСТВУЕТ

Есть prepared-механизм:

```python
oa.set_prepared_value(u"GVL_TEST.Mode", u"1")   # значение СТРОКОЙ
oa.write_prepared_values()
```

**Важно:** при нескольких подготовленных значениях и одном вызове
`write_prepared_values()` применяется только последнее. Пишите **по одному**:

```python
for nm, val in RESET:
    oa.set_prepared_value(nm, val)
    oa.write_prepared_values()
```

Для чтения: `oa.read_value(name)` и `oa.read_values([...])`.

## 1.8. Чек-лист «почему пустой лог»

1. Скрипт лежит в OneDrive → staging не сделан.
2. В скрипте `import` модуля, который обращается к `projects` напрямую.
3. Соседний проект держит CODESYS.
4. Остался `*.~u` от прошлого прогона.
5. Имя лога не совпадает с именем скрипта.
6. Скрипт больше ~25 КБ — загрузчик молча не исполнил.
