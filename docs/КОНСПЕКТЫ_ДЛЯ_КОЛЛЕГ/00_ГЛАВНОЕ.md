# ГРАБЛИ CODESYS: КОНСПЕКТ ДЛЯ КОЛЛЕГ (Z80 и 6502)

Практические заметки из разработки эмулятора **Intel 8080 + CP/M 2.2 + I/O**
на CODESYS 3.5 SP17 в режиме FBD. Всё ниже — проверено на практике, часто
дорогой ценой. Цель: чтобы вы не потратили на это время повторно.

Проект-источник: эмулятор 8080 (218 тестов, все PASS). Ваши проекты (Z80,
6502) структурно ближе к нему, чем кажется: ограничения среды одинаковые,
различается только система команд.

## 1. ТРИ ПРАВИЛА, КОТОРЫЕ СЭКОНОМЯТ ВАМ НЕДЕЛИ

### Правило 1. Любая проверка должна измерять свой охват

«0 ошибок» ничего не значит, если проверка не видит 90 % связей.
Мы четырежды считали проект чистым, а ошибка пряталась именно в непроверенной
зоне. Каждая проверка обязана печатать:

* сколько связей реально проверено;
* сколько осталось неразобранными (`UNK`);
* сколько блоков неизвестного типа;
* сколько пинов не найдено в интерфейсе.

Последние три — «слепые зоны». Пока их число не ноль, «0 находок» — ложь.

### Правило 2. Ошибку локализует КОМПИЛЯТОР, а не глаза

Headless-CODESYS печатает `C32: Невозможно конвертировать тип 'BYTE' в тип
'BOOL'` — без имени POU и сети. GUI печатает `POU (Network N)`, headless —
нет. Не ищите глазами: делите проект бисекцией (файл 04).

### Правило 3. Пустое тело вызывающего МАСКИРУЕТ ошибку в вызываемом

Тело FB генерируется, только если его кто-то вызывает. Пока вы проверяете
«а не в этом ли POU ошибка?», опустошая его, вы гасите весь поддерево
вызовов. Именно так мы полдня считали зависимости «чистыми».

## 3. ЧТО НЕ РАБОТАЕТ В ЭТОЙ СРЕДЕ ВООБЩЕ

* **Визуализация (VISU) из скрипта.** Рефлексия: 0 методов, 0 фабрик из 81.
  Только вручную в GUI.
* **Два прогона CODESYS одновременно.** Приложение однопроцессное, сосед
  убивает ваш процесс через `taskkill`.
* **Чтение `.py` и запись логов в папке OneDrive.** CODESYS не может —
  нужен staging в локальную папку (`C:\...`).
* **Скрипты длиннее ~25 КБ** загрузчик молча не исполняет — делите на модуль
  и короткий драйвер.

## 4. ЕСЛИ СОВСЕМ КОРОТКО

1. Staging в локальную папку, `taskkill` перед запуском, лог-файл дописывать
   построчно.
2. Fan-out запрещён: каждый выход — ровно в один вход, размножайте элементы.
3. Вызов FB объявляет только те выводы, которые читает, и в порядке чтения.
4. Не читайте GVL-ячейку в той же сети, где пишете.
5. Любая проверка печатает свой охват.
6. Ошибку ищет компилятор бисекцией, а не глаза.
7. Тесты гоняйте дважды.
