## 2. Что осталось: слой CP/M (единственная незакрытая часть)

### 2.1. Найден дефект

Проверки 1, 2, 4, 5, 6 набора CP/M сравнивают **длину** журнала консоли
(«журнал вырос на N знаков»). Журнал растёт и от повторных приглашений `A>`,
поэтому проверки могут быть PASS и тогда, когда CCP не выполняет ни одной
команды.

Доказательство — **дамп журнала** в отчёте прогона (06.11.2026, 17:19):

```
\r\nA>.\r\nA>.\r\nA>.\r\nA>.\r\nA>.\r\nA>.\r\nA>.\r\nA>.\r\nA>.\r\nA>.\r\nA>…
```

Журнал целиком состоит из `CR LF A >`: CCP принимает **CR каждый цикл** и
каждую команду выполняет **пустой**. Набранные тестом `DIR`,
`TYPE README.TXT` и `HELLO` до диспетчера не доходят. При этом `DoneCpm`
выставляется по таймауту (`cpm_moved` = «журнал вырос / две команды»), а не
по факту выполнения — поэтому набор выглядит завершённым.

### 2.2. Что уже пробовалось

| Попытка | Результат |

Изменение в репозиторий **не включено** |
| Проверки по содержимому (`DI`, `HELLO`, `COM`, `TY`, `HELLO.COM`, `HELLO FROM`) вместо длины журнала | Схема собирается, но кодогенерация даёт `C32: BOOL → UINT` — нужна отдельная проработка типов. В репозиторий не включено |

### 2.3. Что нужно, чтобы закрыть (порядок действий)

1. Найти причину «CCP читает CR каждый цикл». Гипотезы, которые надо
   проверить измерением: источник `ConIn_Ready` помимо теста (HMI/инициализация
   выставляют готовность с `ConIn_Char = 0`), порядок сетей подачи и приёма в
   одном скане, начальное значение `ConIn_Char`.
2. Ввести **проверки по содержимому** в `TEST_CPM`: искать `DI`, `HELLO`,
   `COM`, `TY`, `HELLO.COM`, `HELLO FROM` в журнале (поиск по «хвосту»
   кольцевого буфера на событии исполнения команды). Заготовка и методика —
   в комментариях `generator/pou_testcpm.py` (`ПРОВЕРКИ ПО СОДЕРЖИМОМУ`).
   Понадобится аккуратная обвязка типов: выход `OR`/`AND` в `IF` напрямую
   даёт `C32` — нужно предварительное преобразование.
3. Сделать `DoneCpm` честным: завершать набор по факту выполнения команд
   (счётчик `CCP_Cnt`), а не по росту журнала.
4. После зелёного прогона обновить `docs/14_РЕЗУЛЬТАТЫ_ТЕСТОВ.md` и
   `README.md` (сейчас они заявляют 218/218 — это **не соответствует** дампу
   журнала).

## 3. Что НЕ входит в сдачу и почему (осознанно)

| Пункт ТЗ | Почему не закрыт |
|---|---|
| Страница VISU | В CODESYS 3.5 SP17 визуализация создаётся только через GUI: у скриптового API нет ни одного метода `visu` (проверено полной рефлексией, `gen_visu.py`). HMI-слой (`GVL_HMI`, `FB_HMI_Update`) готов — страницу рисуют мышью. |
| Заглушки BIOS `LIST`/`PUNCH`/`READER` | Печатающего устройства и перфоленты нет; привязывать не к чему. `Unimpl_Cnt` фиксирует обращения. |
| BDOS 24 | Возвращает адрес вектора входа и не меняет состояние — статистическая функция по определению. |
| Реальные модули ввода-вывода | В установке нет профиля с физическими адресами `%IB/%QB/%IW/%QW`; адаптер `FB_IO_Adapter_HW` компилируется, но обмен не с чем проверить. |
| Watchdog в миллисекундах | Считает сканы: библиотека измерения времени не используется сознательно. |
