# Тесты: где они и почему их не видно как `.py`

В этом репозитории тесты **не являются внешними скриптами**. Они — часть самого проекта
CODESYS: три программы, которые выполняются в той же задаче, что и эмулятор, на том же
процессоре 8080, теми же схемами FBD. Это принципиально: внешний тест мог бы проверять только
API, а здесь проверяется **фактическое поведение эмулятора внутри ПЛК** — с реальными сканами,
реальными защёлками и реальным порядком выполнения.

| Программа | Кейсов | Что проверяет | Генератор |
|---|---:|:---:|---|
| `TEST_8080` | 199 | Ядро Intel 8080: MOV/MVI, INR/DCR, переходы, стек, загрузка/сохранение, арифметика, логика и флаги | [`../generator/pou_test8080.py`](../generator/pou_test8080.py) |
| `TEST_CPM` | 9 | Слой CP/M 2.2: приглашение `A>`, эхо `DIR`/`TYPE`, каталог, содержимое файла, счётчики CCP и ловушек, **запуск настоящей `.COM`** | [`../generator/pou_testcpm.py`](../generator/pou_testcpm.py) |
| `TEST_IO` | 10 | Аппаратный ввод-вывод: `OUT`/`IN`, аналоговый масштаб, порт без канала (STUB/FAULT), `IN` через процессор, watchdog | [`../generator/pou_testio.py`](../generator/pou_testio.py) |

Данные кейсов (ожидаемые значения, байты программ, маски флагов) — это **один массив структур**
`GVL_TEST.Tests` типа `ST_TestCase`, сгенерированный [`../generator/pou_test_defs.py`](../generator/pou_test_defs.py).
Логика прогона — в схемах FBD: одна и та же для всех кейсов.

## Как прогоняются

`TEST_8080` идёт первым в очереди задачи и управляет процессором через штатный порт доступа CP/M;
дальше `PLC_PRG_CPM` вызывает процессор, затем `TEST_CPM`, затем `TEST_IO`. Прогон идёт сам,
пока не выставятся признаки `Done8080`, `DoneCpm`, `DoneIo`, после чего
[`../generator/run_online.py`](../generator/run_online.py) читает результаты по онлайн-сессии и
формирует отчёт `report/stage4_report.md` (таблица «тест → ожидание → факт → PASS/FAIL»).

```powershell
cd ..\generator
.\tools\run_stage4.ps1 -Script .\gen_stage4.py -MaxAttempts 8 -RunTimeoutSec 2700 -NoSrcCopy
```

## Проверки уровня «A» — без CODESYS, за секунды

Отдельный слой инструментов проверяет не поведение, а **корректность генерируемых схем**: они
находят дефект до того, как запустится сборка (которая занимает минуты). Именно они, а не
компилятор, ловят молчаливую потерю связей при импорте.

| Инструмент | Что проверяет |
|---|---|
| `generator/dryrun_stage4.py` | Полная сборка PLCopenXML локально, без CODESYS |
| `generator/tools/check_xml.py` | Структурная валидность PLCopenXML |
| `generator/tools/check_pins.py` | Все входы блоков подключены; нет висячих выходов |
| `generator/tools/check_outpins.py` | Вызов FB объявляет только читаемые выходы и в порядке чтения |
| `generator/tools/check_types.py` | Совместимость типов соединяемых выходов и входов |
| `generator/tools/check_names.py` | Имена против ключевых слов IEC и коллизий регистра |
| `generator/tools/check_consistency.py` | Согласованность объявлений и использований |
